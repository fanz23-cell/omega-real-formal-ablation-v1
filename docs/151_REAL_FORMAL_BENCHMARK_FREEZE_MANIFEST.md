## Two real bugs found and fixed BEFORE this freeze (both disclosed, neither hidden)

1. `real_metta_runner.py`'s error parser originally only captured the generic
   `UNKNOWN_SKILL_CALL` wrapper code, not the nested real reason (`ERR:<real_code>`) — fixed
   before the negative-control run so each of the 9 controls could be verified against its
   exact expected specific reason, not just "some rejection happened."
2. `world_case_generator.py`/`validate_all_cases.py`/`run_confirmatory.py` originally seeded
   ALL distractor events (not just the two target claims) into the real Omega/Chroma store.
   This caused real slowdowns/timeouts once N=1000-scale cases accumulated in the same
   collection (`_find_by_provenance_ref`'s full-collection linear scan grows with total
   collection size). Root-caused and fixed: distractors are now real-schema-shaped and
   appear in the LLM-facing prompt (testing whether more context confuses the model, the
   scale axis's actual purpose), but are never seeded into the real store, since
   `grounded_reason()`'s premise lookup is always exact provenance_ref matching, never fuzzy
   retrieval — distractors were never going to be looked up by it regardless of volume.
   `fairness_check.py`'s own forbidden-brand-cue scan also had a false-positive bug fixed at
   the same time (flagging the directive's own `WITHHELD_CONTROL` placeholder text because it
   contains the substring "control" — fixed with an explicit, disclosed exception for that one
   literal token).

## What is NOT yet frozen (deliberately)

The actual LLM system/task prompt TEXT is generated by `contestants.py` (hashed above) at
call time from each case's data — the prompt *templates* are therefore frozen via the code
hash, not as separately-saved static text files, since case content varies per row. A
representative sample of rendered prompts (one per geometry) is saved to
`frozen_prompts/` in the final release package for human inspection.
